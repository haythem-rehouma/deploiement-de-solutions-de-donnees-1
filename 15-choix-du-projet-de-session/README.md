
# Choix du sujet de projet

Chaque équipe doit choisir **un seul sujet parmi les trois sujets proposés ci-dessous**.

Le choix doit être transmis au professeur avant le début du travail. Une équipe ne peut commencer son projet qu’après avoir obtenu la validation du sujet choisi.

## Sujet 1 — WikiPlatform : infrastructure automatisée multi-instances

Concevoir et déployer une plateforme centralisée permettant d’héberger plusieurs instances indépendantes d’une même application. Chaque instance doit posséder sa propre base de données, ses propres utilisateurs et sa propre configuration.

L’infrastructure devra notamment intégrer Terraform, Ansible, Docker, Traefik, Keycloak, PostgreSQL, N8N et un système de sauvegardes automatisées. L’objectif est de construire une plateforme sécurisée, maintenable et facilement extensible.

## Sujet 2 — SuperKuberneteX

Migrer une application multi-services existante depuis Docker Compose vers une architecture Kubernetes professionnelle.

L’équipe devra déployer le frontend, le service d’authentification, le service de paiement et trois instances applicatives indépendantes. Le projet devra également intégrer PostgreSQL, Redis, un Ingress Controller, des volumes persistants, des Secrets Kubernetes, le Horizontal Pod Autoscaler ainsi qu’un système de monitoring avec Prometheus et Grafana.

L’objectif est de livrer une plateforme Kubernetes scalable, résiliente, sécurisée, supervisée et automatisée.

## Sujet 3 — Chaîne CI/CD complète pour un projet applicatif libre

Concevoir une chaîne CI/CD entièrement automatisée pour une application choisie par l’équipe.

Le projet devra utiliser un dépôt Git structuré avec des branches, des pull requests et un pipeline d’intégration continue comprenant le build, les tests automatisés, l’analyse de qualité et la production d’un artefact.

Le pipeline de déploiement continu devra ensuite publier automatiquement l’application vers un environnement cible, par exemple une machine virtuelle, un serveur, un environnement Docker, Kubernetes ou une plateforme cloud.

La gestion sécurisée des secrets, la documentation du pipeline et les preuves d’exécution seront obligatoires.

## Consigne de sélection

Chaque équipe doit remettre les informations suivantes :

1. Le numéro du sujet choisi : **Sujet 1, Sujet 2 ou Sujet 3**.
2. Le nom de l’équipe.
3. Les noms des membres.
4. Le nom proposé pour le projet.
5. Une description de cinq à dix lignes.
6. Les principales technologies envisagées.
7. L’environnement de déploiement ciblé.
8. La répartition initiale des responsabilités.

Une fois le sujet validé, aucun changement important de technologie, d’architecture ou d’objectif ne pourra être effectué sans l’autorisation du professeur.
